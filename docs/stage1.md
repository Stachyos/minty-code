# 第一阶段：单 Agent 编程闭环

本阶段让同一个 Agent 通过浏览/搜索、读取、补丁、测试和证据检查完成编程任务。工作台与 SWE-bench 评测共享 `worker.py` 主循环及 `coding_tools.py` 的工具协议、修改策略和验证判断，评测的工具在题目容器内执行。

## 使用

1. 启动 Docker Desktop 的 Linux 引擎及本地项目。
2. 新建会话，在「工作文件」中导入代码目录或添加文件。目录导入保留相对路径，跳过隐藏配置、密钥、依赖、构建产物、本地 data 目录和常见二进制文件。当前仅支持 UTF-8 文本，单文件 1 MB、工作区 25 MB / 2000 文件。
3. 给出问题和验收要求，例如「定位加法函数的错误，修复后运行已有测试，不要改测试降低要求」。
4. 在「修改与验证结果」中查看本轮差异、测试结果与限制；工作流程页面展示实际工具与 Hook 事件。

## 工具

| 工具 | 行为 |
| --- | --- |
| list_files | 按文件名模式分页列出文件，排除隐藏目录、依赖和构建输出 |
| search_text | 字面文本搜索，返回路径、行号与相邻代码 |
| read_file | 按行范围读取，并返回文件 SHA-256 |
| apply_patch | 校验文件 SHA-256、唯一原文匹配，支持多文件创建/替换/删除；全部预校验，写入失败时回滚本次已写部分 |
| get_diff | 对比本次运行开始时的文件快照，包含新增/删除文件；不依赖用户仓库的暂存区或提交 |
| run_tests | 在隔离环境运行测试，返回退出码、数量、耗时和源代码指纹 |

`write_file`、`edit_file` 保留兼容入口，也使用新的路径检查与修改实现。外部编辑并发检查属于协作保护，不等同于操作系统隔离或跨进程事务锁。

## 测试执行边界

普通工作台测试运行于 `minty-coding-tests:1` 的临时 Linux 容器，只得到工作区的临时副本，没有真实 API Key 或项目外宿主机目录，测试时没有网络。测试产生的文件不会回写原工作区；Docker 不可用时返回「测试环境不可用」，不会退回宿主机执行。

支持 unittest、pytest、Node 内置测试，以及 npm test 和 Maven/Java 17 测试。首次使用准备基础镜像。npm/Maven 依赖准备只向构建环境提供清单（package.json/lockfile 或 POM），不提供源代码、.npmrc、settings.xml、.env 或凭证；依赖下载完成后再在断网容器执行测试。npm 安装脚本禁用。私有依赖、原生构建依赖或特殊多模块项目可能需要额外环境配置；不能运行时如实报告，不把它计为测试通过。Python 基础镜像包含 pytest，其他第三方 Python 包需要扩展镜像提供。

评测复用官方题目镜像中已安装的环境，不使用普通工作台的依赖镜像；在同一隔离容器运行所选测试，最后仍由独立官方评分器执行隐藏测试。

## 完成判断

- 执行结束和任务做对是两个概念。没有验证数据的旧记录显示「未保存验证证据」。
- 验证结果分为：测试已通过、验证未通过、修改尚未验证、本次未修改文件。
- 测试必须实际发现并运行测试；零测试不能记为通过。
- 测试绑定源代码指纹，测试后再修改代码会使旧证据失效。
- 修改已有测试或测试配置时需要人工复核，不直接记为已验证。
- 模型准备结束但未运行测试时，工作台会为可识别的 Python、Node、npm 或 Maven 项目自动选择测试。当前有效测试失败时，最多两次反馈给模型继续修复，仍受总轮数与时限约束。
- 通过所选测试并不能证明所有用户要求都已满足，验收范围会明确显示。

生命周期提供 input、before_tool、after_tool、stop 四个回调扩展点和事件。第三方 Hooks 插件管理、完整审批、通用任务隔离、检查点恢复属于后续阶段。

## 固定评测与对照

评测页新增「第一阶段固定题集 v1 · 10 题」，定义在 `benchmarks/swe-lite-stage1-v1.json`。题集的 10 个 ID 均属于 Lite test，覆盖 5 个仓库，属于固定内部回归集，不是完整榜单分数。

实验保存题集、模型、预算、数据和执行代码指纹。选择相同题集重复评测后，可选择基线逐题查看改善、回退和环境异常；题目、模型、预算或数据版本不同会标记不可直接比较。仍应多次重复实验评估波动，不根据一个小题集的单次涨分宣称通用能力提升。
